# STRATUM

Unified API access. Centralized key management.

STRATUM is a Windows desktop workspace for connecting external AI providers,
organizing encrypted API credentials, testing live endpoints, and understanding
request reliability. It is built with Electron, React, TypeScript, and SQLite.

## Requirements

- Windows 10 or 11 (x64)
- Node.js 20 or newer
- npm 10 or newer
- At least 1 GB free disk space for packaging (the unpacked app is ~350 MB)

No Visual Studio build tools are required. `better-sqlite3` is pinned to v12,
which supports Node 20 (the version bundled in Electron 33) and publishes a
matching Electron prebuild. v13 requires Node 22 and crashes Electron 33 at
startup.

## Development

```bash
npm install
npm run dev
```

`npm run dev` first runs `npm run native`, which downloads the `better-sqlite3`
binary built for the installed Electron runtime. Electron and your local Node
use different ABIs, so this step is required after every `npm install` or
Electron upgrade. `npm start` and `npm run capture` do the same.

Useful checks:

```bash
npm run typecheck   # node + renderer TypeScript
npm run build       # production bundles in out/
npm start           # preview the production build
```

## Packaging

```bash
npm run dist:dir    # unpacked app in release/win-unpacked (quick check)
npm run dist        # typecheck, build, and NSIS installer in release/
```

`npm run dist` produces `release/STRATUM-Setup.exe`. It runs `npm run native`
first, so the installer always contains the Electron-compatible SQLite binary.
The installer is per-machine, allows a custom install directory, and creates
desktop and Start-menu shortcuts. Local user data in `%APPDATA%\STRATUM` is
preserved on uninstall.

Code signing is optional. electron-builder signs the app and installer
automatically when `CSC_LINK` (path or base64 of a `.pfx`) and
`CSC_KEY_PASSWORD` are set in the environment. Without a certificate the build
succeeds but Windows SmartScreen may warn on first run.

Build resources live in `build/`:

| File | Purpose |
| --- | --- |
| `icon.ico` | App, installer, and uninstaller icon (generated by `npm run icon`) |
| `icon.png` | 512 px source mark for the website or store listings |
| `LICENSE.txt` | License shown by the installer |
| `installer.nsh` | Custom NSIS install/uninstall hooks |

The icon is drawn from the same geometry as the in-app `StratumMark` component;
`scripts/make-icon.mjs` rasterises and packs it without image dependencies.

## Publishing a release

1. Bump `version` in `package.json` and add a matching `CHANGELOG.md` section.
2. Run `npm run dist`.
3. Run `npm run release:website` to copy the installer to
   `website/downloads/STRATUM-Setup-<version>.exe` and write
   `website/release.json` with the SHA-256 checksum and size.
4. Upload `website/downloads/` and `website/release.json`, then point
   **Settings → Updates → Manifest URL** at the published `release.json`.

`release:website` accepts `--base-url <url>` (or `STRATUM_DOWNLOAD_BASE_URL`),
`--installer <path>`, `--notes <text>`, and `--no-copy`.

The updater downloads only over HTTP(S), requires a valid SHA-256 checksum, and
enforces a 500 MB limit.

## Download website

`website/` is a static site — no build step, no framework:

| Path | Purpose |
| --- | --- |
| `index.html` | Landing page: hero, features, screenshots, security, download |
| `styles.css` | Dark theme matching the app, responsive down to phone widths |
| `app.js` | Reads `release.json` for version/size/checksum, renders notes |
| `release.json` | Release manifest, also used by the in-app updater |
| `downloads/` | Installers served by the download buttons |
| `assets/screenshots/` | Real screenshots; CSS previews show until they exist |

Preview it over HTTP (the page fetches `release.json`, which browsers block on
`file://`):

```bash
npm run preview:website          # http://localhost:4173
npm run preview:website -- --port 8080
```

Upload the whole `website/` folder to any static host. The page links downloads
relatively, so the installer works from the same directory without editing HTML.

## Screenshots

```bash
npm run capture
```

This builds the app, launches Electron in capture mode, seeds demo data, visits
every route, and writes PNGs to `website/assets/screenshots`. Pass
`--no-build` to reuse an existing `out/` bundle.

## Data locations

| Path | Contents |
| --- | --- |
| `%APPDATA%\STRATUM\stratum.db` | Providers, keys, requests, logs, settings (packaged) |
| `%APPDATA%\STRATUM-dev\stratum.db` | Same, for development builds |

API keys are encrypted with Windows DPAPI through Electron `safeStorage` and are
never sent to HrazHub AI.

## Troubleshooting

**The app starts and immediately exits with no window**

The SQLite binary does not match the Electron runtime. Run `npm run native` to
fetch the Electron build of `better-sqlite3`, then rebuild or rerun the
installer. This is the expected symptom of installing `better-sqlite3@13` on
Electron 33 (Node 20).

**The installer builds, but the app is not a valid Win32 application**

The build ran out of disk space and `STRATUM.exe` was truncated. Free at least
1 GB on the build drive, delete `release/`, and rerun `npm run dist`.

**`Cannot create symbolic link ... winCodeSign` during packaging**

electron-builder extracts a tools archive that contains macOS symlinks. Windows
blocks symlink creation unless Developer Mode or elevation is enabled. Extract
the archive once without the macOS payload:

```powershell
$cache = "$env:LOCALAPPDATA\electron-builder\Cache\winCodeSign"
$archive = Get-ChildItem "$cache\*.7z" | Sort-Object LastWriteTime | Select-Object -Last 1
& "node_modules\7zip-bin\win\x64\7za.exe" x $archive.FullName "-o$cache\winCodeSign-2.6.0" -x'!darwin' -snld -y
```

Subsequent builds reuse the cache. Alternatively, enable Windows Developer Mode.

**`Could not find any Visual Studio installation to use`**

Packaging no longer rebuilds native modules (`npmRebuild: false` in
`electron-builder.yml`). If you re-enable rebuilds, install the Visual Studio
Build Tools with the Desktop development with C++ workload.
